# qq-bridge 源码级逆分析（REA 方法）

> 第二轮。第一轮（`11-qq-bridge逆分析.md`）只读了 README/RULES.md，是**文档级**结论。
> 这一轮按 REA（Reverse Engineer Anything）的做法，在副本上做、按类型路由、每批探针一次跑完，
> 并且对每条结论标注证据等级：**［已见］**=代码里直接读到；**［推断］**=由两处代码互证；**［未知］**=没读到，不下结论。
>
> 分析对象：`Derpyu520/qq-bridge` v0.2.1-r2（main 分支归档，2026-11-02 下载）

> 历史分析使用本地 qq-bridge 副本；副本未纳入本仓库。

## 0. 先说结论（三条结构性发现）

1. **"像真人"不是提示词写得好，是状态机加成闸门。** 这个项目里管"像不像人"的代码，绝大部分不在提示词里，而在 `bridge.js` 的唤醒/等待/发送流程里：什么时候醒、要不要回、回之前等多久、一次发几条、每条隔多久、消息太旧还回不回。提示词只负责"语气"。
2. **所有"人味"都是可调数值，而且都有默认值。** 静默 10 秒～2 分钟、合批 8 秒、条间隔 1–3 秒、长间隔 5–10 秒、人格注入 8000 字符、每 4 次唤醒重灌一次、消息 10 分钟算旧账、120 分钟默认不回。**这些数字就是"真人感"的骨架。**
3. **反 AI 味的写法是"禁令 + 可执行替代"，不是形容词。** 原话（`bridge.js:11173`）：「你不是客服：不用有求必应，可以装傻、已读乱回、拒绝推荐」。它给了模型**可以做的事**（装傻、乱回、拒绝），而不是"要自然一点"。

## 1. 链路（［已见］）

```
QQ → SnowLuma(OneBot v11) → bridge.js → DSH 会话(agent) → 模型
                                  ↑__________工具回写__________|
```

四模式：`chat` / `closed-agent` / `reserved`（一代仿真）/ `reserved2`（二代仿真）。
`reserved2` 与前面三者的根本差别：**文本不自动转发**，AI 必须自己调 `qq_send_message` / `qq_send_burst` 才发得出去。［已见 `bridge.js:2740`］

这一点是整条链的地基：**不自动转发 = 模型每轮都要做一次"我说不说"的决定**，而不是被逼着对每条消息作答。

## 2. 唤醒层（决定"这次要不要说话"）

| 机制 | 证据 | 说明 |
|---|---|---|
| 不自动转发 | `bridge.js:2740` | 只有 AI 主动调发送工具才出站 |
| 合批窗口 8 秒 | `bridge.js:849` `batchWindowMs: 8000` | 对方连发三条，8 秒内合成一批再唤醒，不会回三条 |
| 首回复静默下限 10 秒 | `bridge.js:11125-11132` `minQuietMs = 10000`，上限 120 秒 | 收到消息**不立刻回**，先等对方说完 |
| 静默建议 8 秒 | `bridge.js:875` `defaultQuietMs: 8000` | 建议值；对方没说完会自动加长 |
| 没说完 +4 秒 | `bridge.js:9542` `if (looksLikeUnfinished(text)) return 12000;` | 见第 3 节 |
| 沉睡前强制观察 5 分钟 | `bridge.js:836` `preSleepWaitMs: 300000` | 不许"聊两句就潜水" |
| 潜水/唤醒配置 | `bridge.js:11193-11206` | 每次唤醒把「当前是潜水还是活跃 / 有限还是无限 / 哪些触发条件」写进提示词 |

**这是我最缺的一层。** 我们的 App 现在是"你发一句，我立刻回"，光这一点就永远不可能像人。

## 3. 上下文层（决定"它知不知道现在是什么时候"）

### 3.1 时间感（`bridge.js:11043` `buildTimeSenseLine`）

每次唤醒注入的不只是时间，而是**"这条消息有多旧"**：

- 默认阈值：`staleChatMinutes = 10`（10 分钟以内算实时对话）、`staleSilentMinutes = 120`（超过 2 小时**默认不回**）。［已见 `timeSenseCfg()`］
- 三档行为：10 分钟内正常接；10–120 分钟"别用'刚''哈哈哈刚看到'这种实时语气，先确认话题还在不在"；超过 120 分钟"默认不回，直接 `qq_mark_read` 收尾；除非明确在找你且回答仍然有用，那开头必须带时间感（'这条我才看到'）"。
- 还有一条**"旧账"警告**：本次唤醒如果消息本来就旧，会直接打 `⚠️ 本次属于「旧账」`，并禁止秒回语气。

### 3.2 半句话检测（`src/v2-wait.js:13` `looksLikeUnfinished`）

- 结尾是 `。！？…～` → 认为说完了；
- 结尾是"的/了/吗/呢/吧/啊/呀/嘛/是/在/把/被/让/给…"或逗号顿号 → 认为**没说完**，多等 4 秒；
- 模型等不下去时，允许发**催话短句**：`['什么', '啥', '你说啊', '然后呢', '？']`。［已见 `UNFINISHED_PROMPT_REPLIES`］

"然后呢"这三个字，比任何提示词都像人。

### 3.3 人格注入节奏（`bridge.js:10306-10380` `roleForWake`）

- 每次唤醒都拼完整角色卡很贵（3–6k 字符 ≈ 2–4k token），所以：角色卡变了/换了 DSH 会话 → 立刻全量；之后**每 `injectEveryNWakes = 4` 次唤醒**全量一次；其余只给**一行提醒**。［已见 `bridge.js:1049`］
- 两个细节值得抄：
  - **签名里带 DSH 会话 id**（`bridge.js:10355`）：`/reset`、换模式会重建会话，此时必须立刻重新全量——只按文件签名的话，重置后前几轮只有一行提醒，"人格等于没注入"。
  - **8 秒去重窗口**（`bridge.js:10365` `injectDedupeWindowMs`）：同一次唤醒里提示词可能构建两次（投递 + 复核），不去重会把"每 4 轮"消耗成"每 2 轮"。
- 注入上限 `role.maxInjectChars` 默认 8000，允许 1000–20000。［已见 `bridge.js:1046`］

### 3.4 记忆（`bridge.js:9548` `formatMemoryV2`）

跨会话记忆 + 每轮注入；另外 `state/slang.json` 存"群聊黑话表"，由 `slang-learner.js` 从最近消息里提候选、**联网搜索确认、人工确认**后才注入。提候选前会转义群聊文本，防 prompt injection。［已见 `slang-learner.js:1-22`］

## 4. 节律层（决定"发出来是什么形状"）

### 4.1 分条（`qq_send_burst`）

- 默认开启，**按空格拆成多条**（一代遗留），二代改成显式数组。［已见 `bridge.js:791-793`、`857-859`］
- `burstMaxMessages: 8`：一次最多 8 条，防止刷屏。
- 条间延迟三档（`computeGapsV2`，`bridge.js:8603-8630`）：
  - `fixed`：统一值（`gapMs` 或逐条 `gaps`）；
  - `byLength`：`base 800ms + 每条字数 × 20ms`（字越多，"打字"越久）；
  - `auto`（默认）：普通间隔在 `1000–3000ms` 随机；有 `longGapProbability` 的概率插入 `5000–10000ms` 的长间隔（像去倒了杯水）。
- 所有间隔都会被 `clampGapV2` 夹在 100ms 到 10000ms 之间。［已见 `bridge.js:8597`］

### 4.2 两条"像不像人"的软校验（这是全项目最妙的地方）

1. **中文空格检查**（`bridge.js:10261` `findCjkSpaceWarning`）：两条中文之间出现半角空格 → "真人一般不这么打"，返回软提醒。
2. **断句边界检查**（`bridge.js:10285` `findSplitBoundaryWarning`）：某条以逗号/顿号结尾、或以"的/了/吗/呢/吧"等需要接后续成分的词结尾，下一条又紧跟中文 → 判定"把同一句话拆成了两条"，提示合并或把断点挪到完整句边界。
   - 还专门维护了一个 `COMPLETE_SHORT` 白名单（`好的/行了/算了/知道了/嗯/哦…`），避免把"好的"这种完整短句误判成半句。

**关键：这两条都是"软提醒，不拦截、不改写"**——交给模型自己修，而不是程式化地替它改。这跟"把人写成规则"是两种思路。

## 5. 表达层

- 表情包：`sticker-lib.js`，注入"表情策略提示 + 候选表情"（`promptMaxStickers` 默认 8 条）。
- 语音：`voice-core.js`（21.6 KB）。
- 媒体：`media-normalize.js` 统一图片/表情/转发的规格。
- 转发消息：`forward.js`。

## 6. 审计层（这一层我们完全没有，但答辩会被问）

`src/sensitive.js`：所有出站文本过两道闸门——① 启发式正则（本机路径、凭据赋值）；② 已知令牌**精确名单**（因为裸 32 位 hex 不匹配正则，而 32-hex 又正好是表情 md5/图片 URL 的形态，加进正则会大面积误伤）。

判定前先**归一化**：NFKC（全角→半角）、剥零宽/双向控制字符、吃掉空白与 `._-`、对疑似 base64 片段尝试解码后再判一遍。注释里写得很直白：攻击者只需要"看起来一样、字节不同"就能绕过逐字匹配。

## 7. 可移植清单（对我们的《回血实验室》）

版本基线：v0.16 / versionCode 17 / 152 单测。下表"现状"是**已经做过的**。

### P0（不做就永远像客服）

| # | 机制 | 我们现在 | 怎么落地 |
|---|---|---|---|
| 1 | 首回复静默 + 合批 | ❌ 秒回 | `ChatScreen` 里收到用户消息后先起一个 8–10 秒可取消窗口，用户继续说话就重置；窗口到才发请求 |

## 8. 不照搬

| 它的做法 | 我们不用的理由 |
|---|---|
| 空格拆条 | 一代遗留兼容，我们用显式数组更干净 |
| 群聊/多人群聊状态机（participation、拍一拍、@、指定成员唤醒） | 我们是单人日常，没有"群"这个对象 |
| OneBot / SnowLuma 协议层 | 我们不走 QQ |
| 200+ 行 markdown 安全不变量校验 | 那是给"用户可编辑预设提示词"防呆用的，我们的性格页只存一段话 |
