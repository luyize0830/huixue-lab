# 技术验证记录 001：普通手环实时心率读取

> 本文档直接服务于《项目测试文档》与《技术研究报告》的"可行性验证"章节，请勿删除。

## 1. 验证目标

证明**不依赖厂商 SDK / 厂商账号 / 云服务**，仅用标准蓝牙协议即可从消费级手环读取实时心率，
从而支撑本项目的核心架构决策：**设备无关（有手环更好，没手环也能用）**。

若此路不通，则整个"用真实生理状态驱动建议"的产品前提不成立，必须退回"仅手机传感器"方案。

## 2. 验证环境

| 项 | 内容 |
|---|---|
| 测试日期 | 2026-10-30 |
| 手机 | 小米 24122RKC7C，HyperOS V816，Android 16（API 36） |
| 穿戴设备 | 小米手环 9 Pro |
| 开发环境 | Android Studio，Kotlin，Jetpack Compose，minSdk 26 |
| 测试 APK | `tech-demo/ble-hr/app-debug.apk`（包名 `com.example.blehr`） |
| 连接方式 | BLE GATT，USB 仅用于安装 |

## 3. 技术方案

采用蓝牙 SIG 标准化心率服务（Heart Rate Service），不使用任何厂商私有协议：

| 用途 | UUID |
|---|---|
| 心率服务 HRS | `0000180d-0000-1000-8000-00805f9b34fb` |
| 心率测量特征 | `00002a37-0000-1000-8000-00805f9b34fb` |
| 客户端特征配置描述符 CCCD（开启 notify） | `00002902-0000-1000-8000-00805f9b34fb` |

数据解析：`0x2A37` 首字节为 flags，**bit0 = 0 时心率占 1 字节（uint8），bit0 = 1 时占 2 字节（uint16 小端）**。
实现见 `tech-demo/ble-hr/MainActivity.kt` 的 `parseHeartRate()`。

前端流程：扫描（12 秒）→ 列表点选设备 → `connectGatt(TRANSPORT_LE)` → 发现服务 →
订阅 `0x2A37` 的 notify 并写 CCCD 使能 → 收到回调即解析显示。

## 4. 操作步骤

1. 手环开机并与手机配对（仅系统级配对，**不要求**打开小米运动健康的连接）。
2. 手环端**开启「心率广播」**（连续测量模式）。
3. 手机端**强制停止「小米运动健康」**，释放其对 BLE 链路的占用。
4. 打开测试 App → 授予「附近的设备」权限 → 等待扫描结果。
5. 在设备列表中点击手环 → 观察心率数值是否随身体状态变化。

## 6. 过程中遇到的问题与解决（可直接用于"测试用例"与"踩坑记录"）

### 问题 1：Android Studio 点击 Run 安装失败

报错：

```
The application could not be installed: INSTALL_FAILED_USER_RESTRICTED
Installation via USB is disabled.
```

原因：小米/HyperOS 对 ddmlib 的安装通道做了限制，与代码无关（编译本身成功）。
解决：改用命令行安装，并补上 `-t`（APK 被标记为 test-only）：

```bash
adb install -r -t app-debug.apk
```

不加 `-t` 时报 `INSTALL_FAILED_TEST_ONLY: Failed to install test-only apk. Did you forget to add -t?`

### 问题 2：App 一打开就提示"权限被拒绝"，且系统设置里没有"位置信息"

原因：`AndroidManifest.xml` 中 `ACCESS_FINE_LOCATION` 声明了 `android:maxSdkVersion="30"`，
该权限在 Android 12+ 上**根本不存在**；但运行时代码仍把它列入必须授予的权限，
导致 `checkSelfPermission` 永远返回 `DENIED`，连权限弹窗都不会出现。

```xml
<!-- 错误写法（在 API 31+ 设备上导致必然失败） -->
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION"
    android:maxSdkVersion="30" />
```

解决：Android 12+ 只申请 `BLUETOOTH_SCAN` + `BLUETOOTH_CONNECT` 两项。
因为 `BLUETOOTH_SCAN` 已声明 `android:usesPermissionFlags="neverForLocation"`，
扫描 BLE 本就不需要定位权限；`ACCESS_FINE_LOCATION` 仅保留给 Android 11 及以下。

> **经验沉淀**：声明了 `maxSdkVersion` 的权限，在更高版本系统上等同于"未声明"，
> 任何"必需权限列表"都必须与 manifest 的 SDK 范围保持一致，否则会表现为静默失败。

### 问题 3：连接不稳定 / 扫不到设备

原因：小米运动健康长期占用手环的 BLE 连接。
解决：测试前强制停止该应用；手环需佩戴在身上才能输出有效心率（离开皮肤可能无数据）。

## 7. 对产品设计的直接影响

1. **主数据源确定**：BLE 心率广播（实时、低延迟、无需账号），作为"状态判断"的客观信号之一。
2. **不绑定任何厂商**：样本代码不引入厂商 SDK，后续换 OPPO/华为/其他手环原理相同，理论上可切。
3. **降级路径明确**：无手环用户退化为"手机传感器 + 自评打分"，产品不崩，符合"设备无关"定位。
4. **权限门槛可控**：只需「附近的设备」一项权限，显著降低首次使用摩擦。
5. **演示可行性确认**：答辩现场可现场戴手环、实时展示心率曲线变化——演示脚本成立。
