## 1. 产品定义

- **是什么**：一个装在手机上的"个人实验助手"。它读你手机的连续使用时长、久坐时长，以及（可选）手环的实时心率，判断此刻状态；在状态下滑时给你 2–3 个 5 分钟内能做完的小行动；你做完打个分，它记住"哪种事对你真有用"。
- **不是什么**：不是健康报告、不是打卡、不是情绪诊断、不是让你"更自律"的工具。
- **边界**：不给医学建议；不做血氧/压力/情绪的诊断式结论；所有建议都能关、能改、能删。

### 1.1 设计原则（评审会被问到的四条）

1. **先承认处境，再给方案**：打开先说"你连续用了 95 分钟"，而不是直接弹任务。
2. **选项优于指令**：永远给 2–3 个，永远有"都懒得做"的退路。
3. **可解释**：每个分数能展开看扣分项；每条推荐能说出"你试过几次、平均几分"。
4. **打扰是特权**：默认克制，两次提醒至少隔 50 分钟，状态好且没久坐就闭嘴。

## 2. 用户与场景

**目标用户**：18–24 岁在校大学生，有智能手机，部分人有手环；长时间自习/写代码/赶 DDL；宿舍—图书馆—教室三点一线。

| 场景 | 触发信号 | 用户此刻想要 | 系统该做的 |
| --- | --- | --- | --- |
| S1 图书馆学崩了 | 连续使用 ≥90min + 心率偏高 | 别再逼我"坚持" | 给 3 个不出声、能坐着做的 3 分钟行动 |
| S2 深夜收尾 | 23:00 后 + 屏幕还在亮 | 想停下来但停不下 | 只推"能收尾"的动作（闭眼、热敷、喝点东西） |
| S3 久坐不动 | 计步器 60min 无变化 | 没意识到自己僵住了 | 一条通知：起身接杯水，或下楼走一圈 |
| S4 考前一周 | 连续多天低分 | 想知道有没有用 | 图谱：哪个时段最差、哪种行动最救急 |
| S5 通勤路上 | 场景=地铁/公交 | 只有 5 分钟 | 排除要躺下/要出声的行动 |

### 3.2 关键功能明细

#### F-01 状态评估

- **输入**：心率、静息基线（会话内最低心率）、连续专注分钟、近 1 小时前台分钟、当前小时、久坐分钟。
- **规则**（阈值即产品定义，全部有单测）：
  - 心率超基线 ≥15 → −22；≥8 → −10
  - 连续专注 ≥120 → −18；≥90 → −12；≥60 → −6
  - 深夜（≥23 或 <5 点）→ −15
  - 近 1 小时前台 ≥40min → −8
  - 久坐 ≥90 → −12；≥60 → −6；**数据缺失时不扣分**
- **输出**：`score(5..100)`、三档状态（低/中/高）、一句 headline、可展开的 reasons 列表。
- **验收**：五信号全报警时得分 25（有单测）；任一信号缺失时不得编造扣分理由。

#### F-05 回血池

- 26 个默认行动，覆盖 6 类：动一动 / 静一静 / 找个人 / 玩一下 / 歇一下 / 吃点喝点。
- 每个行动含：emoji、标题、**耗时（1–10 分钟）**、分类、**cue（第一步具体怎么做）**。
- 支持新增自定义行动、删除、一键恢复默认。
- 验收：增删后重启 App 仍在（SharedPreferences 持久化）。

#### F-06 对话式入口

- **输入**：一句自然语言，例如「在图书馆，还有十分钟，有点撑不住」。
- **解析出三个槽位**：情绪（累/烦/空/还行）、场景（宿舍/图书馆/教室/路上/未知）、时间预算（分钟，支持"十分钟""半小时""1.5 小时"）。
- **组合**：用槽位生成约束（时间上限、深夜模式、场景排除），再调用推荐引擎。
- **回复**：先承认处境 → 说明"我按你说的条件筛了什么" → 给 3 个行动 → 引导回来打分。
- **诚实声明**：当前是**本地规则解析**，不是大模型；架构上留了 adapter 位，后续可替换而不动下游。
- **验收**：图书馆场景不出现需要说话或躺下的行动（有单测）；预算过小时老实说"没剩下合适的"，不硬凑。

#### F-07 主动提醒

- **机制**：AlarmManager 每 30 分钟唤醒一次 `NudgeReceiver`；是否真发由 `NudgePlanner` 决定。
- **发送条件**（全部满足）：开关开着、通知权限已给、距上次 ≥50 分钟、且（分数 <55 或 久坐 ≥60 分钟）。
- **文案**：久坐+低分 / 仅久坐 / 仅低分 三种模板，带一个具体行动名。
- **用户可控**：首页开关一键关闭；关闭后不产生任何通知。
- **验收**：`NudgePlannerTest` 7 条覆盖上述分支；关掉后 `plan()` 必返回 null。

#### F-08 洞察

- 时段画像：上午 6–12 / 下午 12–18 / 傍晚 18–23 / 深夜 23–6 的平均有效分与次数。
- 最有效的三种：按平均分排序，附"心率 ↑/↓/持平"。
- 一句人话总结：`你做了 N 次实验，其中 X% 觉得有用；<时段> 效果最好；目前最吃「下楼走一圈」。`

#### F-09 导出

- 生成带 BOM 的 CSV（时间、行动、状态、前后心率、心率变化、评分），经系统分享面板发出。
- **验收**：标题含逗号时正确加引号转义（有单测）。

#### F-10 深夜模式

- 23:00–05:00 时只推 REST / CALM / FUEL 三类；候选不足时退回全量，**不推空**。

## 4. AI 能力边界（必须讲清楚，评分会查"AI 贡献清晰"）

| 环节 | 做法 | 是不是 AI | 说明 |
| --- | --- | --- | --- |
| 状态评估 | 可解释规则 | 否 | 用规则是为了"每个扣分都能解释"，也便于单测 |
| 意图解析 | 关键词 + 槽位 | 弱 AI（规则） | 后面可换 LLM，接口已留 |
| 推荐 | Thompson 采样（多臂老虎机） | 是（在线学习） | 每个档位独立后验，端侧计算 |
| 文案生成 | 模板拼接 | 否 | 诚实标注，不吹成"大模型生成" |
| 提交材料 | AI 辅助编程记录 | 是 | 按附件 7 模板填写，附原始会话导出 |

> 答辩口径：**我们把 AI 用在"该学的地方"（推荐策略的在线学习），而不是把一切都塞给大模型。** 这既符合端侧隐私，也让每个决策可解释。

## 5. 数据与隐私

- 全本地：SharedPreferences（记录、行动池）+ 本机传感器；**不上传、不联网**。
- 权限只用得到 4 个：蓝牙（可选）、使用情况访问、身体活动、通知。
- 每个权限都能拒绝，拒绝后自动降级并**在界面上标明"演示数据"**，不假装有数据。
- 一键清空记录；导出的 CSV 由用户自己决定发给谁。
