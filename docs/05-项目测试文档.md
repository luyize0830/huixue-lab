## 1 测试计划

## 4 系统测试

### 4.1 真机 BLE 验证

扫描连接小米手环 9 Pro → 发现 `0x180D`/`0x2A37` → 写 CCCD 开 notify，心率随呼吸波动（60–100），三问全过（详见 00 文档）。

### 4.2 模拟器全流程

AVD 走完首页 → 对话 → 计时 → 打分 → 图谱 → 导出，无崩溃；无 BLE 走演示滑杆并打角标。

### 4.3 陪练码端到端

A 生成「听歌」4 分钟码 `1VZJ-BZD0`；B 输入同码，解析出同一行动与同一开始时刻，两端显示「陪练中 · 和对方同一秒开始」，剩余 02:58 同步；超 2 小时与非法字符提示错误、不崩。

### 4.4 结果与建议

BLE 已出清；陪练码证明"不建服务端也能同步"；稳定性**待补**。v0.7 授权后 chip「已接入」；v0.10 三态 85/73/67。

### 4.6 角色与记忆（v0.11）

首页卡片显示头像、名字与情绪；当天首次打开先开口；退出再进能接上。断言在 `PersonaTest`、`ChatCodecTest`。

### 4.5 大模型路径与降级（v0.9.1）

真实 Key 下模型回「三点还撑着…」并给 2 张卡；飞行模式下同一句由本地规则回，尾注「没连上模型…」。

### 4.7 性格与预设（v0.14）

两入口进同一页：五档卡片、自定义框、保存与恢复默认；存 `huixue_persona`，随每条消息进 prompt；断言在 `PersonaPresetTest`、`PersonaTest`。

### 4.8 真人感三段（v0.15–v0.17）

拆条、节奏、合批是三个纯函数：`Humanizer` 切 1–3 条、每条 ≤30 字、客服腔整句丢弃；`Rhythm` 定首条延迟（深夜 2600/早 1800/白天 1200 ms，夹 500–5200）与条间歇（600 ms + 0.35–0.75 倍）；`ReplyGate` 合并 8 s、半句多等 4 s、14 s 必回。实测两条差 81 ms（`1793618882417`/`1793618882498`），只回一条（9.2 秒后，合并上下文）；等待显示「正在输入…」。

### 4.9 主动找人（v0.18）

先 seed 一条 4 小时前的记录（`huixue_chat.xml`），启动 35 秒后出现 `pending_v1` 与通知；卡片「中午了。…上次你说「在赶报告」，后来呢？」，CTA 变「回她一句」，点进去成为开场白。规则在 `InitiativeTest`：23–7 静默、60 分钟冷却、一天 3 次、没聊过不主动。

### 4.10 语音输出的验证方式（v0.19）

TTS 是平台 IO，**不加单测**——单测只能验证"调了没调"，验证不了"念得好不好"。验证靠 logcat 与截图：模拟器抓到 `Synthesis request for locale zho-CHN…` 与 `TTS dispatch: cmn-cn-x-ssa…`，调用链与语言都对；`v19-voice-on.png`、`v19-chat-speaker.png`。音色取决于用户手机的语音包，故只记"能调用、语言正确"，不记"好听"。

## 6 覆盖率与未覆盖部分

按类 21/21；按行**未统计**（未接 JaCoCo）。`ui/App.kt`、`ui/Tabs.kt`、`ChatScreen.kt` 无自动化；BLE 无 Instrumented Test；权限与通知靠手工。`data/LlmClient.kt` 手工验证过（真实 Key → 回复；飞行 → 降级），不适合 CI，**未进单测**；`ui/ReportScreen.kt`、`ui/PersonaScreen.kt`、`ui/Speaker.kt` 纯 UI 未覆盖。

未覆盖：多天记忆（仅单日复现）；纯聊天空 `actionIds` 样本不足；登录页无 UI 测试；五档语气差异仅人工观察；语音音色取决于设备语音包、模拟器无法判定；双人群聊不适用（单用户）。

风险：逻辑层回归有保障，**界面与设备层全靠手工**，是最大短板。
