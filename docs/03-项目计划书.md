## 1 项目概述

### 1.1 项目背景

大学生缺的不是健康知识，而是"知道该歇，却不知道此刻做什么、做多久、有没有用"。典型：图书馆专注 90–120 分钟后需要不出声的 3 分钟；期末周 23 点后停不下来。

现有方案两类缺口：**记录类**（打卡、番茄钟）只记录不判断；**报告类**（睡眠分、压力分）只给结论、不给下一步，分数是黑箱。通用建议不分场地、时间与社交条件。

需求证据：以 N=1 自用原型做技术验证，无正式实验日志；10 人访谈**尚未完成**，两周试用未开始，本文不引用访谈结论与百分比。

### 1.2 项目内容

一句话：**用手机 + 一块普通手环读真实状态，状态下滑时推荐 1 个 5 分钟内能做完的小行动（来自用户自己的"回血池"），做完打 3 秒分，长期积累"哪种回血方式对我真的有效"的个人图谱。**

| 步骤 | 输入 | 输出 | 页面 |
| --- | --- | --- | --- |
| 理解处境 | 心率、连续使用、久坐、时段 | 状态分 5–100、三档、一句结论、可展开依据 | 首页 |
| 提供方案 | 档位 + 回血池 + 历史记录 | 2–3 个候选，各带推荐理由 | 推荐页 |
| 用户行动 | 选中的行动 | 倒计时 + 手机振动 | 计时页 |
| 反馈校准 | 1–5 分 + 前后心率 | 一条实验记录 | 反馈页 |
| 长期沉淀 | 全部记录 | 时段画像、有效榜单、心率变化、CSV | 图谱页 |

定位边界：**不是健康报告、不是打卡工具、不是情绪诊断**，不给医学建议，不做"压力等级"这类结论。

### 1.3 创新点

**1.3.1 技术：主客观双信号校准。** 客观侧读心率相对静息基线的抬升，主观侧读 1–5 分自评，交叉验证——只信心率会被"刚爬完楼"骗，只信自评会被"我觉得还行"骗；两个字段都保留。

**1.3.2 功能：回血池由用户定义。** 候选来自用户真正想做的事（散步、弹琴、撸猫、冲澡），26 个默认行动只是起点，可增可删。休息从系统派的任务变成用户自己的奖励。

**1.3.3 其他：角色与打扰配额。** 以"实验助手"身份给假设（"你还没在这个状态下试过它"）不下指令；提醒 50 分钟冷却，<55 分或久坐 ≥60 分钟触发，状态好不打扰。

## 2 技术方案

### 2.1 总体架构

三层：**UI**（Compose，12 屏 + 手写导航）→ **领域**（纯 Kotlin：`StateEngine`、`Recommender`、`IntentParser`、`InsightsEngine`、`NudgePlanner`、`Pairing`）→ **数据**（`Repo`/`Store`/`ScreenUsage`/`SessionMath`/`ActivityTracker`）。领域层不依赖 Android 框架，因此能用 JVM 单测固定口径。

| 选型 | 采用 | 替代方案 | 代价 |
| --- | --- | --- | --- |
| 手环数据 | 标准 BLE HRS `0x180D/0x2A37` 直读 | 厂商 SDK / 厂商云 / Gadgetbridge | 无账号、无云依赖、换品牌便宜；读不到睡眠/血氧/压力 |
| 手机行为 | `UsageStatsManager` + `TYPE_STEP_COUNTER` | 自建前台服务统计 | 免常驻耗电；需用户去系统设置授权 |
| 推荐 | Thompson 采样（Beta 后验） | 平均分 / ε-greedy / UCB | 自带探索、端侧瞬时完成；需样本积累 |
| 存储 | SharedPreferences + `org.json` | Room / SQLite | 零依赖零迁移；不支持复杂时间窗查询 |
| 状态判断 | 可解释阈值规则 | 分类模型 | 每笔扣分可解释、可单测；个体适配靠反馈 |

### 2.2 功能详述

已实现 33 项：状态评估、推荐、计时与振动、反馈持久化、26 个行动池、对话入口（规则）、主动提醒、洞察、CSV、深夜模式、BLE 心率、使用统计、计步久坐、清空、陪练码、语音输入、健康历史；v0.5–v0.6 重做界面结构（底栏、页签、详情页、热力格）；v0.7 手环搜索与「我的」独立；v0.8 启动图标；v0.9 报告页、HRV、可选模型（110）；v0.9.1 Key 校验；v0.10「大肥鱼」（114）；v0.11「小夜」：人设、记忆（129）；v0.12 接入模型独立页；v0.13 认脸页与通知延后；v0.14 性格可编辑（136）；v0.15 拆条；v0.16 节奏；v0.17 合批与「回得慢但一定回」（161）；v0.18 主动找人：有上限、有安静时段、说得像她（173）；v0.19 语音输出：系统 TTS，默认关、离开即停、念不出写明原因（173）。未实现 2 项：手环振动（私有协议）、云端同步。

### 2.3 关键技术

- **状态评估**：五条规则累加扣分（心率 ≥15 扣 22、≥8 扣 10；专注 ≥120/90/60 扣 18/12/6；深夜 −15；屏幕 ≥40 分钟 −8；久坐 ≥90/60 扣 12/6），`100 − 扣分` 截 5–100，<40 低、<70 中、其余高；信号缺失不扣分、不编理由。
- **推荐**：每个"行动×档位"维护 `Beta(1+成功, 1+失败)`（成功 = 评分 ≥4），采样排序取前 3；零样本加 0.18 探索。
- **提醒**：`AlarmManager` 每 30 分钟唤醒，`NudgePlanner` 决定是否发。
- **对话入口**：本地关键词 + 槽位解析（情绪/场景/时间预算），**不是大模型**，留了 adapter 位。
- **陪练码**：8 位 Base36 承载 40 bit（版本 3+分钟 6+行动 id 哈希 15+epoch 分钟低 16），两台设备本地解码，不联网、无服务端，2 小时有效。

### 2.4 其他相关技术

Compose 单 Activity、`sealed class Screen` 手写导航；通知渠道 + 手机振动；CSV 经系统分享导出；计算全在端侧，不联网。

## 3 项目计划

### 3.1 可行性分析

- **技术**：小米手环 9 Pro 实测读通标准 HRS（扫描→连接→订阅→心率随呼吸变化）；161 个 JVM 单测全绿；AVD `Medium_Phone_API_37.0` 跑通主流程，两台实例跑通陪练码。核心技术风险已出清。
- **资源**：零现金投入。开发机与手环为队员自有，Android Studio 与 JDK 17 免费，无付费 SDK 与云服务。
- **市场**：目标用户 18–24 岁在校大学生，门槛是"有智能手机"，手环只作增强。变现与留存数据均未验证，本文不作商业结论。

主验证指标：推荐接受率（推荐后开始计时的比例）、主观有效性（评分 ≥4 占比）、行动前后心率差、使用 7 天后的图谱条目数；一致性指标是自评与心率变化方向是否相符。上述指标目前均**无样本**。

## 5 总结与展望

当前版本回答"此刻该做什么"与"这件事对我有没有用"，判断权留在用户手里。下一步：①补齐真实用户证据；②Health Connect 已能只读步数与睡眠，下一步把睡眠纳入基线、改善静息近似；③把规则解析换为大模型 adapter（接口已留）。
