# 页面与交互设计

> R1 / 2026-11-27。先验证流程可理解性，再投入高精度视觉与动效。

## 1. 信息架构

- **现在**：时间、场景、可选处境、一个首选、备选、进行中的行动。
- **记录**：按日期回看、主观反馈、我的方法；收藏和行动库从这里或首选下方进入。
- **我的**：数据导出/备份/清空、设备和权限、通知、可选陪伴能力、关于与模式说明。

计时、反馈、行动详情为任务页，不与一级导航争抢注意力。任务中按返回键，给“继续 / 暂停并稍后继续 / 结束本次”的明确选择，不静默丢会话。

## 2. 页面规格

| 页面 | 首要问题 | 主要内容与操作 |
| --- | --- | --- |
| P01 现在 | 我现在可以做什么？ | “给自己几分钟”；1/3/5 分钟；可见的场景；可选处境。首次没有默认时间，提示先选时间；选择后在本页直接更新首选，不多加提交一步。已有会话则先展示恢复卡。 |
| P02 首选卡（与 P01 同屏） | 为什么是这个，怎么开始？ | 一个动作名、时长、具体第一步、一条真实理由；主按钮“开始 X 分钟”；次操作“看看其他方法”“换一个”“改条件”。 |
| P03 计时 | 我该怎么做，还剩多久？ | 大号剩余时间、第一步、暂停/继续、提前结束。屏幕可关闭，不用动画诱导盯屏。 |
| P04 反馈 | 刚才有没有帮助？ | 显示完成或提前结束；1–5 分文字标签，无默认值；“保存反馈”“先不评价”。成功后“记下了，回到你的事情吧”。 |
| P05 记录 | 上次做了什么，值不值得再试？ | 日期、动作、计时结果、评分或未评价；筛选真实/演示/历史未知；可查看来源与再次尝试。 |
| P06 我的 | 我能控制什么？ | 导出、备份、删除与可选能力；权限按功能触发，开关说明行为，不把配置项堆回首页。 |

## 3. 关键文案与空态

| 情况 | 文案方向 | 下一步 |
| --- | --- | --- |
| 初次没有记录 | “还没有休息记录。先找一个现在能做的小方法。” | 去现在页 |
| 没设备信号 | “先按你选的时间和场景推荐，设备数据可稍后添加。” | 正常继续 |
| 无符合条件候选 | “当前没有同时满足这些条件的方法。”并列明限制 | 改时间、改场景或自选；不暗中放宽 |
| 暂停恢复 | “这次休息暂停着，还剩 X。” | 继续 / 结束 |
| 提前结束 | “这次提前结束了。” | 可评价，不写“完成一次” |
| 未评分 | “这次没有评价。” | 记录可见，不计入有帮助比例 |
| 数据保存失败 | “这次还没保存成功，内容已保留。” | 重试 / 继续保留 |
| 历史来源未知 | “旧版本没有完整记录来源，这些记录单独保留。” | 查看 / 导出 |
| 演示模式 | “演示数据，不计入你的真实记录。” | 明确退出演示 |

避免“压力超标”“恢复了 20%”“你的最佳方法”等缺乏依据的结论。处境名称沿用日常语言，不把“有点烦”解释为心理诊断。

## 4. 视觉原则

维持安静、轻量的米白与深青绿色方向。主按钮始终唯一突出；时间和第一步比角色插画重要。图标配文字，颜色不能是唯一状态提示。保留历史形象素材的兼容入口，新主流程先不依赖它们。

不设置连续打卡、排行榜、失败惩罚或吸引反复打开的奖励。微反馈用于确认保存成功、暂停生效等实际变化。

## 5. 原型使用说明

打开 [交互原型](prototype/index.html)，可检查选择条件、首选与备选、开始、暂停、提前结束、评分/跳过和记录回看。所有数据都是设计演示，刷新重置；原型不是实际产品、不是对用户研究的替代。

**原型限制**：未接 Android 持久化、传感器、真实推荐学习、导出与备份、通知及跨进程恢复。看到按钮或示例规则不代表对应 Android 功能已实现。原型验证“理解与选择”，不能验证后台可靠性或健康效果。

建议走查：

1. 不配置任何外部服务，选择图书馆、1 分钟，找到一个安静方法。
2. 查看备选并换一个，确认当前限制仍可见。
3. 开始、暂停、继续、提前结束；确认文案和记录没有伪装完整完成。
4. 跳过反馈；确认出现“未评价”，不是默认 3 分。
5. 完成另一轮并评分，回看记录；确认计时结果与评分各自独立。
6. 清空演示记录先取消，再确认；确认没有无提示的数据丢失。

生产版本的跨重启和备份等验收见 [PRD](02-prd.md)，不以原型走查代替。
