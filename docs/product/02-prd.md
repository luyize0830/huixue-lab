# 产品需求与验收

> R1 / 2026-11-27。以下均为待实现需求；现有 v0.27 能力与缺口明确分列。

## 1. 核心流程与非目标

入口：现在 → 选时间/场景/处境 → 首选行动 → 计时 → 可选反馈 → 记录 → 返回自己的事情。

已有会话优先恢复，不能为新首页丢弃进行中的行动。首次进入不用资料页、权限申请或模型设置挡住入口。个性签名、头像和设备设置可在“我的”中稍后完成。

本轮不重写整个应用、不更换包名、不新增云端账户、不训练新模型，也不把设计原型当作正式发布。

| --- | --- | --- |

## 3. 推荐与反馈契约

- 场景初始为“图书馆 · 可修改”，首次时间显式选定；后续可沿用上次选择但必须显示当前值。处境可跳过，不为省操作自动猜测。
- 动作库保留稳定 ID，补充可验证的环境标签（是否需出声、躺下、离开座位等）。未知标签的自定义动作不能默认满足安静场景，用户补充后再进入自动推荐；仍允许在个人行动库主动自选。
- 先过滤，再排序。除用户预算外，保留现有深夜规则；所有场景条件以页面已确认的选项为准。预算不足时给出具体限制和修改入口。
- 当前“脑子累/眼睛累”等处境不是生理状态档。新增情境对象，不强行映射成 LOW/MID/HIGH。没有足够真实传感器数据时以中性先验或非个性化顺序推荐，不以默认 95/25 分钟制造精确分数；是否启用新情境后验必须单独验证。
- 有足够合格样本才可使用现有 Thompson 思路个性化；策略版本、匹配条件和有效样本数必须可追溯。首次可解释理由只能是时长、场景、第一步等已知事实。
- 换一批产生新推荐轮次；展开备选、重组画面、返回同一批不重复记曝光。显式跳过、换批、离开、未决各自可区分，强杀不能推断为拒绝。
- 评分 1–5，初始无选中；文案为“这次休息对你有帮助吗？”；允许跳过，空值不是 0 或 3。
- 计时走完、提前结束、取消分别保存。早停评价可见，但不混入完整计时行动的个性化训练；未评分不更新后验。计时走完不等于身体动作已经被验证执行。

## 4. 数据契约与迁移

以下字段为设计目标，名称可在实现评审时调整，语义不可混用。

| 对象 | 最少字段 / 规则 |
| --- | --- |
| 使用目的 | `usageMode = REAL / DEMO / UNKNOWN_LEGACY`。由明确模式和迁移规则决定，与权限和有没有传感器无关。 |
| 信号来源 | 每项分别保留 `SELF_REPORT / DEVICE / MISSING / SIMULATED / LEGACY_UNKNOWN`、采集时间和可用性；过期读数不伪装实时。REAL 会话不得使用模拟信号。 |
| 情境 | 场景、预算、可空处境、时区、当地日期；每次开始时固化快照。 |
| 推荐轮次 | roundId、展示时间、候选 ID、顺序、策略版本、情境快照、usageMode、结束结果；反馈不能通过动作名或相近时间猜关联。 |
| 会话 | sessionId、可空 roundId、entryPoint、launchSource（DIRECT / APP_NOTIFICATION / UNKNOWN）、可空 notificationId、行动快照、usageMode、开始/结束时间、实际计时秒数、结束类型、可空 rating、反馈状态。入口页面与启动渠道分开记录。 |
| 反馈状态 | PENDING / SUBMITTED / SKIPPED；与计时结束类型独立。重复提交同 sessionId 不能重复生成记录或学习两次。 |
| 结束类型 | 新会话为 TIMER_ELAPSED / ENDED_EARLY / CANCELLED；历史缺失为 LEGACY_UNKNOWN。进程终止本身不产生完成事件，恢复后继续原 sessionId。 |
| 导出 | 建议新增 rounds-v2.csv 与 sessions-v2.csv，注明 schemaVersion、appVersion、时间窗口和截断情况；保留旧导出兼容入口。 |

**旧数据处理**：

1. 升级前形成可恢复快照；新解码器接受现有备份 v1，新格式使用显式版本。旧 App 不支持新备份时须提前说明，不承诺双向兼容。
2. v0.27 历史使用目的统一迁移为 UNKNOWN_LEGACY。旧 `demo=true` 可能只是未授权，`demo=false` 也不证明实际研究身份；两者都不用于推断真实或纯演示，原标志仅作为历史元数据保留。原字段、行动、评分、已有 ID 与时间不变。
3. 历史记录继续可见、可导出，但不进入新真实指标与新推荐训练。界面解释“这些历史记录的来源未完整记录”，不能悄悄删除。
4. 进行中的旧会话保留并恢复，以未知来源完成；迁移中不新建第二次会话。不更换包名、不卸载用户 App、不改正式签名。
5. 删除记录须同步重建相关学习统计；清空/恢复备份不能留下幽灵后验。备份失败时不发布半份内存状态。
6. 历史缺失的开始时间、实际秒数、时区和结束类型保持未知；不能用计划时长补实际时长或把旧评分当作计时完成。空 sessionId 保持不可关联；若需要本地展示键，用幂等的迁移记录键并明确它不是会话关联证据。保留独立历史视图，不强塞进新版完整会话漏斗。

现有缺口可核对：[RecommendationLog](../../app/src/main/java/com/example/blehr/logic/RecommendationLog.kt)、[LabData](../../app/src/main/java/com/example/blehr/logic/LabData.kt)、[Recommender](../../app/src/main/java/com/example/blehr/logic/Recommender.kt)、[InsightsEngine](../../app/src/main/java/com/example/blehr/logic/InsightsEngine.kt)、[BackupCodec](../../app/src/main/java/com/example/blehr/logic/BackupCodec.kt)。当前两份 CSV 缺少共同的完整来源与评分关联，不能直接得到新版漏斗。

## 5. 必须通过的场景

| 场景 | 预期 |
| --- | --- |
| 全新安装，拒绝权限，断网 | 真人仍可走完行动流程；来源为 REAL + 缺失设备信号，不填演示分数 |
| 图书馆、1 分钟、无合适动作 | 明确空态和修改条件入口，不给 3 分钟或需要出声的行动 |
| 点击开始后立即锁屏/强杀 | 恢复同一会话、同一行动和正确剩余时间，不重复曝光/开始 |
| 暂停、后台、重启设备 | 暂停不耗时；使用既有跨重启恢复机制，记录无法确定的异常，不伪造时长 |
| 提前结束、取消、跳过反馈 | 三种语义保持独立；计时结束和真实指标不混算 |
| 保存失败或重复点击提交 | 保留可重试状态；提示失败，不丢反馈、不生成两条记录 |
| 演示完成高评分后切回真实 | 真实记录、后验和指标无变化 |
| v0.27 备份、归档行动和进行中会话迁移 | ID 与内容不丢，未知来源可见，不篡改旧记录 |
| 恢复备份、清空、再导出 | 关联一致，无残留统计；取消清空不影响数据 |
| 跨午夜或切换时区 | “今天”按保存的当地日期语义计算，不把全历史记录数当今天完成数 |

## 6. 非功能验收

核心闭环离线可用，默认不调用云模型。手机 360dp、系统字体放大到 1.3 倍、TalkBack、触控目标不少于 48dp 均需实测。计时运行不阻止锁屏；关键保存和迁移有错误恢复。

冷启动与首选等待时间先在指定测试机测基线，再制定可兑现的性能门槛；本轮不引用未测的 1.5 秒/80MB 等历史目标作为已有成绩。
