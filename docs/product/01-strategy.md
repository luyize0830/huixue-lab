## 2. 服务对象与核心情境

**首批目标用户（产品决策）**：使用 Android，每周有多次独立学习任务，常在图书馆或自习室学习的大学生。不以购买手环、配置模型服务或长期打卡作为进入条件。

**核心任务**：当我看不进去、眼睛累或坐得太久，但还有事情想继续做时，帮我选一件安静、时间够、现在能执行的休息；做完之后，我希望记住这次是否有帮助。

主场景先做安静学习间隙；宿舍和户外作为场景约束的兼容项。通勤安全、长期睡眠管理、心理咨询和运动训练不纳入本轮主流程。

**待验证假设**：

- H1：目标用户确实反复遇到“想短休但不知道做什么”，且现有做法没有充分解决。
- H2：一个首选加少量备选能减少选择负担，而非让用户觉得失去控制。
- H3：用户愿意给一次简短反馈，并在另一日自主再次使用。
- H4：回看个人记录比增加角色、积分或更多图表更能帮助下一次选择。

## 3. 产品承诺与边界

对用户说：“给自己几分钟，找一种适合你的休息方法。”承诺可执行、可拒绝、可回看；不承诺休息一定有效，也不以单次心率变化推断恢复或治疗效果。

五分钟指行动时长。首次选择、可选反馈另计，不暗示所有人的完整流程都在五分钟内。计时只记录应用计时情况，不能证明用户实际执行了动作。

产品不要求每日签到，不制造连续记录压力，不用负面状态评分催促用户。用户可以不给权限、不开通知、不评分、停止行动。

## 4. 功能取舍

| 范围 | 本轮处理 | 理由 |
| --- | --- | --- |
| 情境、时间与行动选择 | 核心；一个首选、最多两个备选 | 直接回答此刻做什么 |
| 可恢复计时、早停、反馈 | 核心；清楚区分完成、早停、退出和未反馈 | 保住闭环及记录真实性 |
| 个人行动、收藏、回顾 | 保留；收进二级页面，少量记录就能回看 | 减少下次选择成本 |
| 备份、导出、删除 | 保留；迁移先验收 | 保护已有用户和数据 |
| 分数、手机信号、BLE、睡眠 | 可选依据，放到“我的”及展开详情 | 不能成为首次成功的前提 |
| 角色聊天、人设、语音、音景 | 保留兼容入口，暂不新增投入 | 先验证核心任务；不删除既有内容 |
| 主动提醒 | 默认关闭；后续用户主动开启 | 先证明主动使用价值，减少打扰 |
| 社交、排行榜、云同步、专有手环振动 | 本轮不做 | 当前不支撑核心验证，增加依赖 |
| 大模型自动决策、为每次推荐调用云模型 | 不进入核心链路 | 本地规则和既有推荐足以验证主张 |

## 5. 差异化与经营判断

差异化假设是“场景可执行的短休 + 用户自己的反馈记忆”，而不是功能数量或模型规模。尚未完成当前竞品研究，不把旧选题底稿中“所有产品都没做”当作事实。

先用免费本地试点验证价值，不引入广告、订阅、云账号或硬件销售。若将来商业化，另做需求、成本和现有素材授权核验；本轮不假定市场规模、收入或获客成本。

## 6. 产品负责方式

产品经理对范围、优先级、验收和证据口径负责。开发先解决数据与迁移，再实现主流程；设计只围绕已确定的任务；研究结果能否定当前方向。每轮评审只回答：用户卡在哪里、证据是什么、下一次改哪一个主要问题。

赛事作为交付约束保留，但报名状态、届次和截止时间须由官方信息核实；不能依据历史底稿中的日期倒排不可兑现的承诺。
