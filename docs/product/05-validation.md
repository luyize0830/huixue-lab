# 用户验证、指标与研究记录

> R1 / 2026-11-27。以下是待执行方案，所有阈值为事前产品决策门槛，不是行业基准、统计显著性或已取得结果。

## 1. 先验证需求，再验证可用与复用

### A. 10 人问题访谈

招募符合目标场景的 Android 学生；不要求购买或佩戴设备。每人约 15–20 分钟，先问最近经历，后展示原型。

1. 最近一次看不进学习内容是什么时候？当时在哪里，接下来做了什么？
2. 那次实际休息了多久？怎么决定做什么？有什么事情当时不方便做？
3. 你有没有不打开任何 App 就解决的方法？哪次休息后更愿意继续自己的事情？
4. 展示原型后，请对方自己找一个适合当时场景的方法。记录操作，不先教路径。
5. 哪些信息让你犹豫？你会在什么时候再次打开它，什么时候绝不会？
6. 对通知、记录与自愿导出有哪些具体顾虑？

若不足 6/10 人能描述近一周至少一次“想短休却难以选择”的具体经历，先调整场景或问题定义，不靠增加功能解决。该门槛是小规模立项筛选，不外推大学生总体。

### B. 5 人首次任务观察

在不配置模型、不连手环、不授予可选权限的条件下，让用户独立完成：选 1 分钟安静行动 → 开始 → 暂停/继续 → 计时结束 → 提交一次反馈 → 找回记录。主持人不指导，帮助后完成单列。

观察首次展示到点击开始的时长、误点、犹豫、返回与求助。目标为至少 4/5 无提示完成；选择时长中位数目标不超过 30 秒，两项都报告实际分布而非只报平均值。未达标先修流程，最多一次主要改动后再招新用户验证，不重复训练同一组人直到“达标”。

原型阶段可验证选择与理解；涉及持久化、离线和权限的正式任务必须用候选 Android 构建重新验证。

### C. 8–12 人、14 天自然试用

仅在来源与关联数据修复、候选包验收后开始。先说明退出、删除及自愿分享方式；练习模式明确为 DEMO，真实试用另起计量窗口。研究同意与匿名编号放在单独研究记录，不为普通使用新增强制研究注册。

不催用、不要求每天凑次数；本轮试点经参与者同意关闭本产品主动提醒，以验证主动使用。若参与者自行开启，记录偏离和启动渠道；通知启动或来源不明的会话不当作已确认自主复用。第 1–3 天处理故障，第 7 天仅问是否遇到问题，不以访谈代替自然复用；第 14 天自愿导出并回访。发生版本变化记录生效时间与受影响人员。

姓名和联系方式不进入仓库。原始自评与设备读数由参与者决定是否分享；不自动上传，也不把聊天内容纳入指标。未导出、退出与无法安装均保留在参与流程说明，不静默删去。

## 2. 五项产品指标

所有“真实”均指明确 REAL 的试点使用；DEMO、团队教学、UNKNOWN_LEGACY 单列。研究人员主动要求的练习不计自主复用。

| 指标 | 分子 / 分母 | 判定用途 |
| --- | --- | --- |
| 跨日自主复用率（核心） | 14 天内至少两个当地日期自主开始真实行动的人数 / 已同意并进入试用期的人数 | 至少一半有跨日复用才继续投入个性化；只打开首页不算开始。不要求评分，避免将复用与反馈意愿混成一个指标。 |
| 首次独立完成率 | 无指导走完规定任务的人数 / 接受首次任务的人数 | 5 人中至少 4 人，未通过先修入口；同时记录求助和每步耗时 |
| 推荐选择率 | 明确选定并成功保存会话的真实首页轮次 / 实际展示的真实首页轮次 | 诊断选择环节，无预设“行业达标线”；收藏/行动库直接开始不混入分母 |
| 反馈完成率 | SUBMITTED 且 rating 为 1–5 的真实已结束会话 / 真实已结束会话 | TIMER_ELAPSED 与 ENDED_EARLY 分层报告；取消不进入分母，跳过与待评仍在分母 |
| 主观有帮助比例 | TIMER_ELAPSED 且评分 4–5 的真实会话 / TIMER_ELAPSED 且已评分的真实会话 | 只说明有反馈者的主观体验；同时报告未评数量、早停评分和退出，不能等同疗效 |

“自主开始”需结合研究期练习记录排除主持人指定任务，且 launchSource 为 DIRECT；通知触发与未知渠道单列，不能仅凭时间猜自主。跨日按会话开始时保存的本地日期计算，不从条目数量推算天数。

逐人报告分子/分母，再给总体合计；分母为 0 写“无可计算样本”。未提供任何日志的人保留在试点总分母，并标注结果未知。复用率下界为已确认跨日复用人数 / 入组人数，上界为（已确认人数 + 因缺失或渠道未知而无法判断的人数）/ 入组人数；这些人各只计一次。不把未观察到等同明确未使用。

下界至少 50% 才进入下一轮个性化；上界不足 50% 则判本轮门槛未达；区间跨过 50% 为证据不足，优先在自愿前提下补齐记录或补测，不能擅自判成功。例如 8 人中确认 3 人复用、2 人未知，范围为 3/8–5/8，结论是证据不足。

另列工程与体验护栏：崩溃、恢复失败、数据丢失、打扰投诉及对应人数。它们是阻断或诊断项，不为了凑“五项指标”隐藏严重问题。

## 3. 事件与去重

| 事件 | 触发与必要关联 |
| --- | --- |
| recommendation_shown | 合格候选真正可见时一次；roundId、候选/顺序、策略版本、情境、usageMode |
| recommendation_resolved | 明确选择/跳过/换批/离开；原 roundId；强杀保持未决，不伪造 skip |
| session_started | 保存成功后一次；sessionId、可空 roundId、入口、launchSource、可空 notificationId、mode、时间及情境快照 |
| session_paused / resumed | 状态真正变更；sessionId；用于解释实际计时，不重复计算开始 |
| session_ended | TIMER_ELAPSED/ENDED_EARLY/CANCELLED；sessionId、结束时间、实际计时秒数 |
| feedback_submitted / skipped | 同 sessionId 幂等处理，评分与跳过互斥；保存失败不算提交成功 |
| data_exported / truncated | 导出时间、应用/格式版本、覆盖窗口与截断数量；只本地记录必要元数据 |

保留期与上限必须显式说明。当前推荐日志最多保留 5000 轮；新版若仍有上限，导出必须说明最早覆盖日期和丢弃量。用被截断的分母计算完整 14 天指标时应标为覆盖不完整。

v0.27 推荐 CSV 有 session_id，但反馈 CSV 缺对应关联和来源；反馈模型也未完整保留来源。正式研究不能通过名称、时间或心率相近来拼接。先实现 F-44/F-47；若只能测试旧版，仅报告主持人观察到的操作可用性，不把旧导出当新版指标。

## 5. 决策规则

- 问题访谈门槛未达：收缩或更换场景，停止扩大开发范围。
- 可用性门槛未达：修入口、理解或反馈，不加新服务。
- 跨日复用上界不足一半：先看哪些场景未发生、为何未打开或不愿再用；不直接加通知、打卡或陪伴。区间跨门槛则记录证据不足；下界达标才继续。
- 有复用但帮助比例低：检查动作是否适合场景、是否执行与评分解释，不能因心率好看宣布有效。
- 有复用且反馈有价值：进入个人方法回顾和更细的推荐试验；要比较策略优劣时另行事前设计对照，本轮不作因果声明。
- 数据丢失、演示污染或隐私误解：先停止扩充试点并修复，不用完成率抵消。
