# 回血实验室 · Android 工程

《回血实验室》是"第二十届全国大学生软件创新大赛"参赛作品（赛题四：AI＋健康）的原型工程。

一句话定位：**手环读状态 → 状态下滑时推荐 1 个 5 分钟能做完的小行动 → 做完打 3 秒分 → 长期积累"哪种回血方式对我真的有效"的个人图谱。**

> 改代码前先看 [`AGENTS.md`](AGENTS.md)：**每次修改后都要跑测试、提交并 push 到 GitHub**（用户 2026-11-03 明确要求），涉及用户可见变化时还要同步 README、`docs/03`–`docs/08`、Release 与桌面交接包。

刻意避开"深蓝黑底 + 霓虹薄荷绿 + 大 emoji"这套常见的生成式观感：一是这个应用白天在户外用得多，深色底在强光下更难读；二是那套观感太像模板，不像一个被人认真挑过颜色的个人工具。反馈页原来用 emoji 表情打分，v0.5 也换成了「没用 / 一般 / 还行 / 有用 / 很管用」五段文字选择。

## 构建

需要 JDK 25（与仓库 daemon 配置一致）和 Android SDK Platform 37.0（compileSdk 37，minSdk 26）。

```bash
# 先将 JAVA_HOME 指向 JDK 25、ANDROID_HOME 指向自己的 SDK
# Windows：GRADLE_USER_HOME 使用纯英文目录；中文项目可加 -PhuixueBuildDir=<英文输出目录>
.\gradlew.bat assembleDebug --console=plain

# 单元测试
.\gradlew.bat testDebugUnitTest --console=plain
```

产物：`app/build/outputs/apk/debug/app-debug.apk`

**安装到小米/HyperOS 设备**：Android Studio 的 Run 会报 `INSTALL_FAILED_USER_RESTRICTED`，请直接用 adb：

```bash
adb install -r -t app/build/outputs/apk/debug/app-debug.apk
```

（`-t` 是因为 debug 包带 testOnly 标记；`-r` 覆盖安装。）

## 已知限制（写进参赛文档时必须如实说明）

1. **演示数据仍保留**：未授权"使用情况访问"时用滑杆代替屏幕信号，UI 明确打"演示数据"角标；授权后自动切换。
2. **静息基线**：当前用"本次会话最低心率"近似，不是设备提供的真实静息心率。
3. **久坐只认"步数变化"**：站着不动会被算作没走动；这是手机的物理限制，不是 bug。
4. **手环振动不可用**：标准 GATT 没有振动服务，需厂商私有协议或通知镜像。
5. **仅支持标准心率服务**：不读睡眠/压力/血氧等厂商专有数据。
6. 包名 `com.example.blehr` 与项目目录 `BleHrDemo` 是技术验证阶段的遗留，正式版会改。

## 账号与设备入口（v0.7）

v0.6 的问题：手环扫描挤在首页一个卡片里，附近设备一多就找不到自己的手环；Health Connect 的「去授权」点了会立刻弹回、看起来毫无反应；底栏没有放账号和个人设置的地方。

v0.7 的处理：

1. **手环搜索独立成页**（`ui/ScanScreen.kt`）——15 秒倒计时、每行显示信号强度与地址尾号、「心率广播」标记，默认只看"像手环的"，可一键切"显示全部"；已连接时顶部绿卡直接显示"已连上谁 · 正在读多少 bpm"。
2. **Health Connect 授权一次点完**（`PermissionsRationaleActivity` + `HealthConnectSource.needsUpdate/installIntent/settingsIntent`）——先判断"有没有装、要不要更新、能不能用"，分别导向应用商店或系统设置；`healthLauncher.launch` 包了 `runCatching`，失败会弹一句人话，不再静默。
3. **底栏第五格「我的」**（`ui/MineScreen.kt`）——账号卡（本地账号，昵称/学校/专业，明写"只在这台手机上"）+ 设备与数据（手环、Health Connect、使用情况、身体活动，每行都有状态 chip + 一键去处理）+ 陪练码入口 + 提醒开关 + 导出/清空 + 关于。

为什么账号是"本地账号"：比赛阶段没有服务器，硬做一个假的云登录既不可信也不诚实；界面里直接说清楚"以后接入 OPPO / 学校账号时，这一层会换成真正的登录"。

## 图标（v0.8）

![icon](docs/icon-512.png)

主题：奶油色「回」+ 一颗麦色指示点，深绿底（`Look.Accent` #3D5A4A）。

三个决定：

1. **用「回」不用闪电**。闪电/爱心/电池这套是工具类 App 的通用图标语汇，换谁都一样；「回」直接对应产品名"回血"，而且和 v0.5 起 App 内的汉字分类贴纸（动/静/聊/玩/歇/吃）是同一套语汇——图标应该是这套语汇的第一个字。
2. **几何按 adaptive icon 安全区收**。圆形遮罩半径是 36/108，方形标记半宽上限 25.4，这里取 24.5（外框中心线 21 + 半描边 3.5），保证 Pixel 一类圆形/圆角遮罩不切角。麦色点也压在这条安全线以内。
3. **矢量前景 + 各密度 webp 兜底**。`drawable/ic_launcher_foreground.xml` 是纯矢量（两条描边圆角矩形 + 一个圆），48px 到 512px 同一份几何；`mipmap-*/ic_launcher.webp` 是给老启动器的方/圆两套位图。

## 实验报告、HRV、可选大模型（v0.9）

这三个都是"为了让评委相信这不是拍脑袋做的"而加的，不是为堆功能。

1. **实验报告页**（`logic/ExperimentReport.kt` + `ui/ReportScreen.kt`）——把记录聚成"按类别 / 按时段"两张表，配三条硬口径：每组少于 3 次**只列不排名**（试过一两次就说"哪种最有效"是在骗自己）、心率变化只统计前后都有值的记录、报告末尾固定写 N=1 不可外推、不做因果断言。可导出 Markdown，直接贴进《技术研究报告》。
2. **HRV（RMSSD）**（`logic/HrvMath.kt`）——从 `0x2A37` 的 flags bit4 里按 2 字节小端读 R-R，`raw*1000/1024` 换算毫秒，先过 300–2200ms 伪迹过滤，再算 RMSSD/SDNN/pNN50；样本不足 8 个就返回 null，界面上写"正在攒够 8 个再算"，设备只广播心率时写"这只设备可能只广播心率（那就算不了 HRV）"，绝不编数。
3. **对话层接大模型（可选）**（`logic/LlmAdvisor.kt` + `logic/JsonLite.kt` + `data/LlmClient.kt`）——用户自己在「我的 · 理解方式」里填 DeepSeek Key 才启用；提示词里限定"只能从清单挑 2–3 件、深夜不挑社交类、图书馆教室不挑要说话的、不给医疗建议"，模型只回 `{"reply","actionIds","minutes"}`，解析失败/超时/断网一律退回本地规则并明说"（刚才没连上模型，这是本地规则给的）"。**没有 Key 时产品功能一点不少**——这是故意的：答辩现场没网也能演。

为什么不用 `org.json`：它在 JVM 单测里会抛 "not mocked"，所以写了个 90 行的 `JsonLite`（去 ``` 围栏、截第一个花括号平衡块、还原转义），保证解析逻辑 100% 可单测。
### 关于 API Key 的三条约束（v0.9.1）

1. **不硬编码、不进仓库**：Key 只在运行时由用户填入，存进 `SharedPreferences`（应用私有目录），代码里没有任何默认 Key。
2. **当场校验**：输入框要求以 `sk-` 开头且 ≥20 位，不合格直接禁用「保存」并给出提示——粘贴掉几个字符是常见事故，存进去只会得到"点了没反应"。
3. **可随时清除**：弹窗里有「清除」，一键删掉本机 Key；关掉开关就完全回到本地规则，不联网也不花钱。
## 大肥鱼（v0.10）

在「我的 · 理解方式」里填了自己的 API Key 之后，首页会多出一只蓝色大肥鱼（`ui/Fish.kt`，纯 `Canvas` 手绘，不引贴图）。

- **它是什么**：一个随精力分变表情的陪伴角色。开心 / 发呆 / 担心三态，担心时头顶冒汗、嘴角下撇，并主动说一句话劝你歇五分钟，点「让它挑一个 →」直接进对话。
- **阈值比档位严格**：担心 <70 分、开心 ≥85 分（档位是 <40 / <70 / ≥70）。67 分界面还写着「还有余量」，鱼已经在担心了 —— 档位负责如实汇报，鱼负责早一点劝你。这条规则抽成了 `FishMoodRule.of(score)` 纯函数，由 `FishMoodRuleTest` 钉死边界，以后调权重不会悄悄改掉产品承诺。
- **为什么只在自己接了 Key 之后出现**：这是「你自己接的模型」带来的角色，不是我们凭空塞的功能；没填 Key 时产品一切照常，只是少这只鱼。
- **对话页**里它的头像也会出现在助手气泡上方（22dp，不播放动画，避免消息列表里一直在动）。

截图：`evidence/v10-fish-happy.png`、`v10-fish-idle.png`、`v10-fish-worried.png`。

## 角色：小夜（v0.11）

大肥鱼退场了。用户要的不是"状态不好时弹一只吉祥物"，是**一个每天能说两句话的人**。

| 模块 | 文件 | 要点 |
| --- | --- | --- |
| 人设 | `logic/Persona.kt` | 名字、语气、边界写在提示词里：话短、不喊加油、不装医生、不叫"主人"、不用 emoji |
| 情绪 | `logic/Mood.kt` | `MascotMood` + `MoodRule`（担心 <70、开心 ≥85）；形象和说话共用同一套阈值 |
| 记忆 | `data/ChatMemory.kt` | 最近 40 轮 + 一句摘要，存在 `huixue_chat`；格式 `u/a\t时间戳\t内容`，坏行跳过不废整份 |
| 主动性 | `ui/ChatScreen.kt` | 当天第一次打开，她先开口（`Persona.greeting`，纯本地生成，不等模型） |
| 形象 | `ui/Girl.kt` | Canvas 自绘二次元头像（蓝发、半眯眼、蕾丝头饰、蝴蝶结），三种情绪；不复用任何现成角色 |

两条设计决定：

1. **她可以只是聊天。** `actionIds` 允许为空 —— 上一版每条回复都硬塞三个按钮，像客服而不像朋友。
2. **她记得你。** 进来先接上历史，摘要会用"上次你说…后来怎么样了？"接话；清空入口在「我的 → 记录」。

单测 129 个：新增 `MoodRuleTest` 4、`ChatCodecTest` 7、`PersonaTest` 7（人设也断言：会自我介绍、会追问、深夜更直接、系统提示词里写了那几条硬规矩）。

## 登录（认脸）与接入模型（v0.13）

「我的」里原来只有一个三字段的小弹窗，第一次打开的人根本不知道要先填。v0.13 把它升级成正式的认脸页，并把顺序理顺。

- **首次启动先认脸**：全屏页，小夜站在上面；填了称呼之后，输入框下方会立刻出现一句「你好，<称呼>。」（不联网、不调模型，纯本地拼字符串），让人先感到"她认得我"。
- **昵称真的会进人设**：`Persona.system(...)` 多了一个 `nickname`，提示词里写死「他让你叫他「X」，你就这么叫，别再问」。开场白也会带名字。填不填都能用，空着就走原来的说法。
- **学校/专业是可选的**：写在页面上「以后要做多人对比会用到」，不填不拦。
- **不拦路**：底部有「先不填，随便逛逛 →」，跳过也能进首页。
- **这不是账号系统**：页面上直说「没有服务器、没有密码、不需要手机号；名字只存在这台手机的 App 私有目录里」。这一条是刻意的——评委问"你的用户数据怎么管"，答"根本没有服务器"比答"我们加密了"更硬。
- **通知权限挪到登录之后**：原来在 `onCreate` 里就问，系统弹窗会盖在认脸页上。现在只有已登录的老用户才在启动时问，新用户走完登录、`onSaved` 回调里再问。

相关文件：`ui/Login.kt`（全屏认脸页）、`ui/App.kt`（`Screen.Login` 与首启判断 `ProfileRepo.current.signedIn`）、`logic/Persona.kt`（`nickname` 进入系统提示词与开场白）、`MainActivity.kt`（通知权限延后）、`ui/MineScreen.kt`（「编辑」改成跳同一个页面，删掉旧的 `ProfileDialog`）。

`ui/Girl.kt` 同时换了发型：从"齐刘海长发"改成双马尾（马尾根部有小发圈），更接近用户给的参考图那种懒散感，也仍然是纯 Canvas 自绘、不用任何第三方角色图像。

## 她说的话可以改（v0.14）

上一版的提示词写成了「规矩清单」：六条规则 + 输出格式，模型照着清单产出一条条
「承认你累 + 给三个动作」的建议，句式还重复，读起来像客服。v0.14 改了三件事：

1. **用示例定语气，不用形容词。** 提示词里直接写对照：
   `他：今天好累 / 你：嗯……累啊。` 以及 `✗ 不要这样：累就累吧，不用撑着。先躺十分钟。`
   模型分不清「自然」和「温柔」，但分得清哪句像人说的。
2. **多数回合不给方案。** `actionIds` 默认是空数组 —— 她可以只是回你一句，
   不是每条回复都要塞三张卡片。这是 v0.11 之后以角色口吻聊天、但仍然像客服的主因。
3. **说话方式抽成一段，用户能改。** 「我的 → 小夜 → 她的性格」里五档：
   小夜（默认）/ 暖一点 / 冷一点 / 欠揍一点 / 我自己写（直接编辑提示词）。

页面上写清了边界：这段文字会随每条消息一起发给**你自己的**模型，不经过我们的服务器；
没接入模型时走本地规则，这段文字不生效。

规则表在两个地方：`logic/PersonaPreset.kt`（预设文案）与 `data/PersonaStore.kt`（本地存储，
SharedPreferences `huixue_persona`，key `preset_v1` / `custom_v1`）。136 个单测覆盖了
「用户改的说话方式原样进提示词」「没传就用默认预设」两条关键行为。

## 回多慢，和"一定回"（v0.17）

用户否决了参考项目里"超过两小时默认不回"的设计。理由很直接：陪伴产品里，
沉默不是克制，是失约——用户对着手机等一条永远不会来的消息，比说错话更伤人。
所以 v0.17 只保留"回得慢"，删掉"不回"：

| 规则 | 值 | 为什么 |
|---|---|---|
| 合并窗口 | 8 秒 | 你连发三条，她回一次，而不是被追着回三次 |
| 半句话多等 | +4 秒 | 以"的/了/吗/然后"结尾像是没说完，多等一等再答 |
| 上限 | 14 秒 | 到点必须回；等待期间显示"正在输入…" |
| 必回 | 硬约束 | 模型空回复时用本地规则兜底，任何异常也补一句 |

代码在 `app/src/main/java/com/example/blehr/logic/ReplyGate.kt`：
`looksUnfinished()` 只判"像不像半句"（句末标点/撤销虚词/白名单短句），
`waitMs()` 决定等多久，`merge()` 把连发的几条拼成一段上下文。

时间感也进了提示词（`Persona.system(...)` 的 `minutesSinceLast`）：
隔了十分钟以上，不许再用"刚看到"这种实时语气；隔了几小时，可以带一句
"这条我才看到"，但**还是要回**。

另外修了一个每轮都被用户碰到的 bug：点了"先不填，随便逛逛"之后，
下次冷启动还会再弹一次认脸页（`ProfileStore.seen/markSeen`，存 `seen_v1`）。

## 她会自己来找你（v0.18）

之前只有你找她。v0.18 加了「主动」这一层，但把频率压得很低——被叫三次以上就变成打扰。

| 规则 | 值 | 为什么 |
| --- | --- | --- |
| 多久没聊才主动 | 状态好 3 小时 / 状态差 2 小时 | 状态差的时候早一点，但她不是打卡机器人 |
| 两次主动之间 | 至少 60 分钟 | 防止连发 |
| 一天最多 | 3 次 | 上限写死，不靠心情 |
| 安静时段 | 23:00–07:00 不主动 | 半夜把人叫醒是最不陪伴的事 |
| 有没读的话 | 不再叠一条 | 一条没看完就再来一条，是催 |
| 检查间隔 | 20 分钟 | 省电，也避免行为像监控 |

她从不说「该休息了」这种模板话。句子由三部分组成：时段开场（「早。」「下午这个点最难熬。」）+ 她自己的事（刚睡醒 / 刚刷到一个视频 / 水开了）+ 追问上次你说过的话。担心的时候不绕弯子，只有一句「今天还行吗？」。

技术上：`logic/Initiative.kt` 是纯函数（`shouldReachOut` 与 `line` 都能单测，12 个用例覆盖上面每一条）；`data/InitiativeStore.kt` 只负责读写磁盘与发通知；`ui/App.kt` 的 30 秒轮询里调一次，`ui/ChatScreen.kt` 打开时把她那句话接到对话开头（`InitiativeStore.clearPending` 之后就不会重复）。

## 让她说话（v0.19）

文字已经像人了，但一个人对着屏幕打字，和"有人应你一声"是两件事。v0.19 加的是**念出来**。

| 决定 | 做法 | 理由 |
| --- | --- | --- |
| 谁来念 | 手机自带的 TTS（`android.speech.tts`） | 不打包音色、不要录音权限、不上传音频，包体也不涨 |
| 默认开吗 | 关 | 第一次见面手机突然开口，比安静更吓人 |
| 念多长 | 超过 120 字截断加"…" | 一口气念两分钟不像人，像导航 |
| 什么时候停 | 离开对话页立刻 `shutdown` | App 在后台念稿子是最尴尬的一种"陪伴" |
| 念不出来怎么办 | 页头写清原因（没引擎 / 没中文语音包） | 不静默失败：否则用户以为"她不会说话" |
| 想重听 | 每条气泡下面一个小喇叭（只在开了语音时出现） | 装饰性的图标不该出现在关掉的功能里 |

实现：`ui/Speaker.kt`（`rememberSpeaker()` 管 TTS 生命周期与失败原因）、`data/VoiceSettings.kt`（开关持久化）、`ui/Look.kt` 新增自绘的 `GlyphKind.SPEAKER`、`ui/ChatScreen.kt` 在 `LaunchedEffect` 里对新到的助手消息逐条 `say()`（历史不念），`ui/MineScreen.kt` 的「小夜」分区加开关。

## 压力、情绪与音乐（v0.20）

### 三个决定

1. **压力优先看心率变异率（RMSSD）**，其次才是「心率比基线高多少 / 连续专注 / 深夜 / 屏幕时长」。
   没有手环数据时不假装能测：`StressBand.UNKNOWN` + 界面上一句「这只是按作息和行为估的」。
   阈值写在 `logic/StressEngine.kt` 顶部（HRV 20/30/45 ms，心率高出 12/20 次，压力分 35/60 分档），
   规则改一个数，`StressEngineTest` 会立刻告诉你哪些说法跟着变了。
2. **情绪是推断，不是测量**。规则顺序刻意是「先生理、再作息与精力、最后兜底平静」，
   界面上写「看起来 / 推断」，依据全部点得开。不做任何医学结论。
3. **音乐不碰版权**。内置的三段音景是 `player/AmbientPlayer.kt` 里用 `AudioTrack` 实时合成的
   （正弦堆叠 + 多频正弦凑出的噪声），采样率 22050、单声道、离开页面即停。
   零音频文件、零版权风险、不增包体，也不需要前台服务权限。

### 文件分工

| 文件 | 作用 |
| --- | --- |
| `logic/StressEngine.kt` | 压力分级 + 情绪推断（纯函数） |
| `logic/MusicSuggestion.kt` | 什么时候推、推哪一段、说什么（纯函数） |
| `player/AmbientPlayer.kt` | `Synth` 合成公式 + `AmbientPlayer` 播放器 |
| `data/MusicBinding.kt` | 记住第三方音乐 App、准备搜索词、一键跳转 |
| `ui/MusicScreen.kt` | 音乐页（音景 / 建议 / 第三方绑定） |

### 第三方音乐 App：只送到门口，不做逆向

QQ音乐 / 网易云都**没有**开放「播放指定歌曲」的公共接口，深链也随版本变。
所以这里只做三件老实的事：记住你常用哪个 App、把「轻音乐」放进剪贴板、
能深链就深链（目前只有 QQ音乐 试了搜索深链），不能就打开 App 让你自己粘一下。

### 已知限制

- 没有 R-R 间期（部分手环只广播心率）时，HRV 永远算不出来 —— 界面上如实说明，不编数字。
- 音频是「音景」不是歌：它的作用是压住环境噪声、给呼吸一个节拍，不是替代音乐 App。
- 合成器有单测（不越界、不静音、三段互不相同），播放器本身没有单测（平台 IO）；
  v0.19 的 TTS 同理。这两处缺口写进了 `docs/05-项目测试文档.md`。

## 连不上模型时，她会告诉你为什么（v0.21）

起因是用户反馈：「软件里总提示没有连上模型」。以前 `LlmClient.ask()` 失败就返回 `null`，
界面只能统一加一句「刚才没连上模型，这是本地规则给的」——401（Key 失效）、404（地址填错）、
超时、压根没接入，全都长一个样，用户无从下手；更糟的是**没填 Key 时也会显示「连不上」**，
而那时她其实只是还没上线。

### 改法：把失败原因变成能显示的数据

| 文件 | 作用 |
| --- | --- |
| `logic/LlmErrors.kt` | 状态码 / 异常 / 未接入 → 一句「怎么修」（纯函数，可单测） |
| `data/LlmClient.kt` | `LlmResult.Ok / Fail(reason)`；新增 `askOutcome()`，`ask()` 保留为薄封装 |
| `ui/ChatScreen.kt` | 失败时把原因写进气泡；未接入时输入框上方给可点的「接入 →」 |
| `test/.../LlmErrorsTest.kt` | 11 个断言：哪种错说哪种话，`NOT_CONFIGURED` 里不许出现「连不上」 |

三种情况现在读起来是这样：

- 没填 Key：气泡里「（还没接入你自己的模型，现在用的是本地规则）」+ 上方常驻提示条。
- Key 失效：气泡里「（Key 不对或已经失效：去控制台新建一个 Key，重新填进来）」。
- 域名不通：气泡里「（域名解析不了：检查网络，或者地址拼错了）」。

### 为什么值得单独修

这不是文案问题。**静默降级会让用户以为功能是假的** —— 他填了 Key、看到「没连上」，
第一反应是「这 App 坏了」，而不是「我的 Key 过期了」。把原因说出来，
用户自己就能修；顺带也保住了 `docs/07` 里那句「失败要说出来，不是悄悄降级」的证据。

### v0.22：说完还得有地方改

用户发来一张截图，上面写着「（模型回的话我没看懂：这个地址可能不是 OpenAI 兼容接口）」，
配一句「这也没有改的地方」。两句都成立，于是又补了三处：

1. **不再把「不像 JSON」当成错误**。真实模型经常不按格式回，直接说一段人话。
   `LlmReplyParser.parse` 现在会把拿不到 JSON 的那段整段当回复（`{"actionIds":[...]}` 这种
   确实是 JSON 却没 `reply` 的，仍判格式错，不硬猜）。
2. **行动清单不再念给用户听**。模型偶尔把给程序看的 `cold | 冷水洗把脸` 抄进回复，
   现在整行过滤掉。
3. **任何失败都能当场去改**。输入框上方的提示条不再只管「没接入」，401/404/超时/格式错
   都把原因摆出来，右侧固定「改设置 →」，点进 `ModelSetupScreen` 就能改地址、模型名、Key；
   「我的」页里那张卡也从「填 API Key」改成「模型已接入 / 设置」，不再只有 Key 一个入口。
