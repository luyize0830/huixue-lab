# 回血实验室 · Android 工程

《回血实验室》是"第二十届全国大学生软件创新大赛"参赛作品（赛题四：AI＋健康）的原型工程。

一句话定位：**手环读状态 → 状态下滑时推荐 1 个 5 分钟能做完的小行动 → 做完打 3 秒分 → 长期积累"哪种回血方式对我真的有效"的个人图谱。**

## 构建

需要 JDK 17 + Android SDK（compileSdk 37，minSdk 26）。

```bash
# 命令行构建（Windows，Android Studio 自带 JBR）
$env:JAVA_HOME="C:\Program Files\Android\Android Studio\jbr"
.\gradlew.bat assembleDebug --console=plain

# 单元测试
.\gradlew.bat testDebugUnitTest --console=plain
```

产物：`app/build/outputs/apk/debug/app-debug.apk`

**安装到小米/HyperOS 设备**：Android Studio 的 Run 会报 `INSTALL_FAILED_USER_RESTRICTED`，请直接用 adb：

```bash
adb install -r -t app/build/outputs/apk/debug/app-debug.apk
```

（`-t` 是因为 debug 包带 testOnly 标记；`-r` 覆盖安装。）

## 已知限制（写进参赛文档时必须如实说明）

1. **演示数据仍保留**：未授权"使用情况访问"时用滑杆代替屏幕信号，UI 明确打"演示数据"角标；授权后自动切换。
2. **静息基线**：当前用"本次会话最低心率"近似，不是设备提供的真实静息心率。
3. **久坐只认"步数变化"**：站着不动会被算作没走动；这是手机的物理限制，不是 bug。
4. **手环振动不可用**：标准 GATT 没有振动服务，需厂商私有协议或通知镜像。
5. **仅支持标准心率服务**：不读睡眠/压力/血氧等厂商专有数据。
6. 包名 `com.example.blehr` 与项目目录 `BleHrDemo` 是技术验证阶段的遗留，正式版会改。

## 账号与设备入口（v0.7）

v0.6 的问题：手环扫描挤在首页一个卡片里，附近设备一多就找不到自己的手环；Health Connect 的「去授权」点了会立刻弹回、看起来毫无反应；底栏没有放账号和个人设置的地方。

v0.7 的处理：

1. **手环搜索独立成页**（`ui/ScanScreen.kt`）——15 秒倒计时、每行显示信号强度与地址尾号、「心率广播」标记，默认只看"像手环的"，可一键切"显示全部"；已连接时顶部绿卡直接显示"已连上谁 · 正在读多少 bpm"。

## 实验报告、HRV、可选大模型（v0.9）

这三个都是"为了让评委相信这不是拍脑袋做的"而加的，不是为堆功能。

1. **实验报告页**（`logic/ExperimentReport.kt` + `ui/ReportScreen.kt`）——把记录聚成"按类别 / 按时段"两张表，配三条硬口径：每组少于 3 次**只列不排名**（试过一两次就说"哪种最有效"是在骗自己）、心率变化只统计前后都有值的记录、报告末尾固定写 N=1 不可外推、不做因果断言。可导出 Markdown，直接贴进《技术研究报告》。
2. **HRV（RMSSD）**（`logic/HrvMath.kt`）——从 `0x2A37` 的 flags bit4 里按 2 字节小端读 R-R，`raw*1000/1024` 换算毫秒，先过 300–2200ms 伪迹过滤，再算 RMSSD/SDNN/pNN50；样本不足 8 个就返回 null，界面上写"正在攒够 8 个再算"，设备只广播心率时写"这只设备可能只广播心率（那就算不了 HRV）"，绝不编数。
3. **对话层接大模型（可选）**（`logic/LlmAdvisor.kt` + `logic/JsonLite.kt` + `data/LlmClient.kt`）——用户自己在「我的 · 理解方式」里填 DeepSeek Key 才启用；提示词里限定"只能从清单挑 2–3 件、深夜不挑社交类、图书馆教室不挑要说话的、不给医疗建议"，模型只回 `{"reply","actionIds","minutes"}`，解析失败/超时/断网一律退回本地规则并明说"（刚才没连上模型，这是本地规则给的）"。**没有 Key 时产品功能一点不少**——这是故意的：答辩现场没网也能演。

为什么不用 `org.json`：它在 JVM 单测里会抛 "not mocked"，所以写了个 90 行的 `JsonLite`（去 ``` 围栏、截第一个花括号平衡块、还原转义），保证解析逻辑 100% 可单测。
### 关于 API Key 的三条约束（v0.9.1）

1. **不硬编码、不进仓库**：Key 只在运行时由用户填入，存进 `SharedPreferences`（应用私有目录），代码里没有任何默认 Key。
2. **当场校验**：输入框要求以 `sk-` 开头且 ≥20 位，不合格直接禁用「保存」并给出提示——粘贴掉几个字符是常见事故，存进去只会得到"点了没反应"。
3. **可随时清除**：弹窗里有「清除」，一键删掉本机 Key；关掉开关就完全回到本地规则，不联网也不花钱。
## 大肥鱼（v0.10）

在「我的 · 理解方式」里填了自己的 API Key 之后，首页会多出一只蓝色大肥鱼（`ui/Fish.kt`，纯 `Canvas` 手绘，不引贴图）。

- **它是什么**：一个随精力分变表情的陪伴角色。开心 / 发呆 / 担心三态，担心时头顶冒汗、嘴角下撇，并主动说一句话劝你歇五分钟，点「让它挑一个 →」直接进对话。
- **阈值比档位严格**：担心 <70 分、开心 ≥85 分（档位是 <40 / <70 / ≥70）。67 分界面还写着「还有余量」，鱼已经在担心了 —— 档位负责如实汇报，鱼负责早一点劝你。这条规则抽成了 `FishMoodRule.of(score)` 纯函数，由 `FishMoodRuleTest` 钉死边界，以后调权重不会悄悄改掉产品承诺。
- **为什么只在自己接了 Key 之后出现**：这是「你自己接的模型」带来的角色，不是我们凭空塞的功能；没填 Key 时产品一切照常，只是少这只鱼。
- **对话页**里它的头像也会出现在助手气泡上方（22dp，不播放动画，避免消息列表里一直在动）。

大肥鱼退场了。用户要的不是"状态不好时弹一只吉祥物"，是**一个每天能说两句话的人**。

| 模块 | 文件 | 要点 |
| --- | --- | --- |
| 人设 | `logic/Persona.kt` | 名字、语气、边界写在提示词里：话短、不喊加油、不装医生、不叫"主人"、不用 emoji |
| 情绪 | `logic/Mood.kt` | `MascotMood` + `MoodRule`（担心 <70、开心 ≥85）；形象和说话共用同一套阈值 |
| 记忆 | `data/ChatMemory.kt` | 最近 40 轮 + 一句摘要，存在 `huixue_chat`；格式 `u/a\t时间戳\t内容`，坏行跳过不废整份 |
| 主动性 | `ui/ChatScreen.kt` | 当天第一次打开，她先开口（`Persona.greeting`，纯本地生成，不等模型） |
| 形象 | `ui/Girl.kt` | Canvas 自绘二次元头像（蓝发、半眯眼、蕾丝头饰、蝴蝶结），三种情绪；不复用任何现成角色 |

两条设计决定：

1. **她可以只是聊天。** `actionIds` 允许为空 —— 上一版每条回复都硬塞三个按钮，像客服而不像朋友。
2. **她记得你。** 进来先接上历史，摘要会用"上次你说…后来怎么样了？"接话；清空入口在「我的 → 记录」。

单测 129 个：新增 `MoodRuleTest` 4、`ChatCodecTest` 7、`PersonaTest` 7（人设也断言：会自我介绍、会追问、深夜更直接、系统提示词里写了那几条硬规矩）。

## 登录（认脸）与接入模型（v0.13）

「我的」里原来只有一个三字段的小弹窗，第一次打开的人根本不知道要先填。v0.13 把它升级成正式的认脸页，并把顺序理顺。

- **首次启动先认脸**：全屏页，小夜站在上面；填了称呼之后，输入框下方会立刻出现一句「你好，<称呼>。」（不联网、不调模型，纯本地拼字符串），让人先感到"她认得我"。
- **昵称真的会进人设**：`Persona.system(...)` 多了一个 `nickname`，提示词里写死「他让你叫他「X」，你就这么叫，别再问」。开场白也会带名字。填不填都能用，空着就走原来的说法。
- **学校/专业是可选的**：写在页面上「以后要做多人对比会用到」，不填不拦。
- **不拦路**：底部有「先不填，随便逛逛 →」，跳过也能进首页。
- **这不是账号系统**：页面上直说「没有服务器、没有密码、不需要手机号；名字只存在这台手机的 App 私有目录里」。这一条是刻意的——评委问"你的用户数据怎么管"，答"根本没有服务器"比答"我们加密了"更硬。
- **通知权限挪到登录之后**：原来在 `onCreate` 里就问，系统弹窗会盖在认脸页上。现在只有已登录的老用户才在启动时问，新用户走完登录、`onSaved` 回调里再问。

相关文件：`ui/Login.kt`（全屏认脸页）、`ui/App.kt`（`Screen.Login` 与首启判断 `ProfileRepo.current.signedIn`）、`logic/Persona.kt`（`nickname` 进入系统提示词与开场白）、`MainActivity.kt`（通知权限延后）、`ui/MineScreen.kt`（「编辑」改成跳同一个页面，删掉旧的 `ProfileDialog`）。

`ui/Girl.kt` 同时换了发型：从"齐刘海长发"改成双马尾（马尾根部有小发圈），更接近用户给的参考图那种懒散感，也仍然是纯 Canvas 自绘、不用任何第三方角色图像。

## 她说的话可以改（v0.14）

上一版的提示词写成了「规矩清单」：六条规则 + 输出格式，模型照着清单产出一条条
「承认你累 + 给三个动作」的建议，句式还重复，读起来像客服。v0.14 改了三件事：

1. **用示例定语气，不用形容词。** 提示词里直接写对照：
   `他：今天好累 / 你：嗯……累啊。` 以及 `✗ 不要这样：累就累吧，不用撑着。先躺十分钟。`
   模型分不清「自然」和「温柔」，但分得清哪句像人说的。
2. **多数回合不给方案。** `actionIds` 默认是空数组 —— 她可以只是回你一句，
   不是每条回复都要塞三张卡片。这是 v0.11 之后以角色口吻聊天、但仍然像客服的主因。
3. **说话方式抽成一段，用户能改。** 「我的 → 小夜 → 她的性格」里五档：
   小夜（默认）/ 暖一点 / 冷一点 / 欠揍一点 / 我自己写（直接编辑提示词）。

页面上写清了边界：这段文字会随每条消息一起发给**你自己的**模型，不经过我们的服务器；
没接入模型时走本地规则，这段文字不生效。

规则表在两个地方：`logic/PersonaPreset.kt`（预设文案）与 `data/PersonaStore.kt`（本地存储，
SharedPreferences `huixue_persona`，key `preset_v1` / `custom_v1`）。136 个单测覆盖了
「用户改的说话方式原样进提示词」「没传就用默认预设」两条关键行为。
